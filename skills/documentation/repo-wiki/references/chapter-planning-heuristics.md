# 章节规划启发式 A–H（完整版）

调度器在 Phase 0 调研完成、进入 D3 之前 Read 本文。**先选 1 条主启发式定骨架，再用其他启发式补章**。具体章节名称由 D3 用户确认落定，不强制任何硬编码命名。

## 主启发式选择

| 项目形态（Phase 0 摘要卡的「类型」） | 首选主启发式 | 常见补充 |
|---|---|---|
| 库 / 框架 / SDK | A 按分层 | D 交叉切面、H 决策 |
| monorepo / 多包 | B 按模块 | A（包内）、D |
| 单体业务系统 | C 按业务领域 | D4 业务切面、F 用户旅程 |
| 多语言 monorepo / 前后端同仓 | E 按子系统 | 子系统内套 A–D |
| CLI / REST / RPC / 状态机 / 集成对接 | F 按旅程或路径 | D、H |
| 微服务 / 多 Lambda | G 按部署单元 | D2 可观测性、D3 部署 |
| fork 项目 / 有 ADR 历史 | 任一主启发式 + H | — |

## 启发式 A：按分层（库 / 框架 / SDK）
有明确层次边界时优先使用。示例：模型层 / 视图层 / 控制器层 / 注册系统 / 插件 / API 门面 / 工程化基础设施

## 启发式 B：按模块（monorepo / 多包项目）
每个 package 一章 + 1-2 章讲跨包协作关系。

## 启发式 C：按业务领域（业务系统，领域边界清晰时）
业务领域 ≈ 顶层 app 目录 + 数据库表簇自然分组。示例：鉴权 / 用户 / 订单 / 支付 / 报表 / 第三方集成

## 启发式 D：按交叉切面（任何项目都可追加为补充章节）
- **D1 工程化**：构建 / 测试 / CI/CD / Lint / Type Check
- **D2 可观测性**：日志 / 指标 / 链路追踪 / 告警 / SLO
- **D3 部署运维**：Docker / K8s / Helm / 配置管理 / 发布流程
- **D4 业务切面**（业务项目）：审计日志 / 权限矩阵 / 多租户 / 国际化

## 启发式 E：按子系统切分（混合栈 / 前后端同仓）
多语言 monorepo 时触发。顶层按子系统分（frontend/ backend/ admin/），每个子系统内再套 A-D。

## 启发式 F：按用户旅程 / API 路径 / 命令分组
- CLI 工具：按子命令分组
- REST/RPC 服务：按 API 路径或资源域
- 状态机型业务：按核心状态机旅程切分
- 集成对接型：每个对接对象一章

## 启发式 G：按服务 / 部署单元（微服务 / 多 Lambda）
每个 `cmd/<service>` 或 Lambda 一组章节 + 1-2 章讲跨服务协议。

## 启发式 H：重大决策型章节（任何项目都可有）
- Fork 决策日志（fork 项目）：`decision-log` 模板，`DECISION_TYPE = fork-delta`
- 架构演进 ADR（非 fork）：`DECISION_TYPE = architectural-evolution`
- 技术栈迁移决策：`DECISION_TYPE = tech-stack-migration`

## 顶层分类按受众生成（D3 草稿确认落定）

顶层目录命名词由 D3 用户确认落定（语义可自由选择），但目录层级本身（受众/章节/页面.md 三层）自 v2.1 起固定，工作 agent 不得输出扁平结构。示例：
- 库类 + 受众「维护者 + 使用者」→ `维护者指南/` + `使用者指南/`
- 业务系统 + 受众「新人 + 业务方」→ `开发指南/` + `业务说明/`
- 内部工具 + 受众「运维」→ `运维手册/`
- 微服务集群 + 受众「SRE」→ `部署与运维/` + `服务详解/`

## 页数与轮数的经验值

- 每章 3–6 页；首要受众 20–40 页，每个次要受众 6–12 页（与 D1 的预估描述一致）。
- 轮数 = 章节按「基础层 → 实体层 → 领域层 → 外围层」分组后的组数 + 1 轮验证，通常 3–7 轮。
- 章节数超过 12 时优先合并同层次的小章，而不是增加轮数。
