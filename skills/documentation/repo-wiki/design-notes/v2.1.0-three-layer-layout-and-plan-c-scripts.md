## 改造背景
在 project-upgrade-tool 上跑 v2.0 暴露三类问题：
1. **交互不友好**：决策点只给字母选项让用户敲编号，期望像 Claude Code 原生工具那样的结构化选择，且允许选项之外的自由输入。
2. **结构错误**：使用者指南的章节编号从维护者指南的 08 往下接成 09、10；两个受众是不同维度，编号应各自从 01 开始；输出也出现过扁平结构。
3. **可靠性**：git diff 解析、schema 读写、事务这类「容易出 bug 的部分」由 agent 现场用 Bash 拼命令，不可审计、不稳定。讨论过 A（MCP server）、B（纯 CLI 工具）、C（skill 保留对话体验 + 脚本承担确定性部分）三案，选 C：无需注册 MCP，SKILL.md 写明何时调用哪个脚本即可。

## 改造目标
- 三层目录结构强制：`{{WIKI_ROOT}}/<受众目录>/<NN-章节>/<NN-页面>.md`，编号按受众独立，每章 README 门面；agent prompt 必须给三层绝对路径。
- 交互执行规范：能力探测分层 Tier 1（结构化工具 `AskUserQuestion`）/ Tier 2（文本）/ Tier 3（CLI），结果缓存 `runtime.json`，`--platform` 可覆盖；D3 因含自由文本编辑保留文本路径。
- 方案 C 脚本：`delta-schema.py`（validate / staging 事务 / update-page / update-sync）、`delta-git.py`（precheck / collect / affected-pages / orphan-scan）、`delta-conflicts.py`（check）；`references/phase-delta-protocol.md` 定义 Δ.-1～Δ.9 与 exit code 约定。
- `--upgrade` 三档路径 + 收尾固定段 8 步脚本化（`release-finalize.sh`、`skill-self-check.py`、`design-notes-lint.py`、`docs-drift-helper.py`、`upgrade-cli.py`、`help.py`）。
- `.wiki-meta/pages/` 按三层路径拆文件（schema v2.1，v2.0 扁平仍可读）；`SKILL_ROOT` 5 级解析协议。
