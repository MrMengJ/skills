# 升级 Plan：v2.1.6 — scale-aware-thresholds-and-hit-reasons

生成时间：2026-09-05 14:32

## 改造背景
iteration-5（v2.1.5）首次生成全绿，但报出四条问题，其中一条是 v2.1.5 自己引入的：(1) source_root 的默认值写成了 '.'，而它是相对 wiki 所在目录解析的，对最常见的 <项目>/.wiki 布局正确值应是 '..'，照文档填反而会把源码根指到 wiki 目录自己；(2) 1800 汉字门槛让四页首稿全部不达标（1486–1640），连续两轮评测都因此多跑一轮补写，对 25 个文件的小项目而言这个门槛本身不合理；(3) 「汉字数」与「非空白字符数」相差 2.3 倍（1892 汉字 = 4440 非空白），SKILL.md 的措辞不足以让人分清，容易按错的口径自评；(4) 章节 README 的模板要求、README.json 要求分散在三个文件里，漏写 README.json 不会有任何报错；(5) 多语言信号「必须询问用户」在非交互模式下没有 fallback。 dry-run 一侧另报：affected-pages 只返回页面名不给命中原因，两轮评测里 agent 都因此重写了一遍反向映射；三个分组之外还有一个静默的第四桶（source_files 为空、primary 只删了一部分的页面全部漏掉）；delta-conflicts.py 不输出 exit-code 约定承诺的 ok 字段；Δ.6 没说内置 template_versions 从哪来；Δ.3/Δ.8 的正文代码块漏了速查表里有的参数。

## 改造目标
source_root 的默认值与文档一致且对常见布局正确；字数门槛按项目规模分档，不再让小项目每次都返工；字数口径在命令与文档里一次说清；章节 README 的要求收拢到一处并可被检查；非交互模式下所有「必须询问」都有明确 fallback。

## 用户文档影响分析
1. README.md：无需改。 2. docs/usage.md：验证命令补 --per-page，§ 1 通过标准同步分档门槛。 3. docs/maintainers.md：无需改。

## 改造主体步骤

SKILL.md 验证规范：门槛按源文件数分档（<50 → 1200、50–300 → 1800、>300 → 2200），命令示例补 --per-page，并明确门槛按汉字数计、与 wiki-stats 报告里的『非空白』列不是一回事。 3. wiki-stats.py 输出里把两个口径的列头写清楚。 4. SKILL.md 目录结构约束一处写全章节 README 的三项要求（README.md 存在、对应 README.json、page_type 取所属章节类型）。 5. SKILL.md 非交互模式补一句：包括多语言信号在内的所有『必须询问』在非交互下取探测到的首选值并在复述里标出。 6. 同步 docs/usage.md。 7. delta-git.py affected-pages 增加 reasons 与 needs_review 第四桶。 8. delta-conflicts.py check 补 ok 字段。 9. 协议正文代码块补齐参数，Δ.5 增加 E 组，Δ.6 说明模板版本来源。
