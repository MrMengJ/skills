# 升级 Plan：v2.1.5 — role-alias-and-source-root

生成时间：2026-09-05 14:04

## 改造背景
v2.1.4 新增的目录型 source 拦截在真实产物上一跑就暴露了三个更深的问题：(1) 规则太宽——车辆管理系统 29 处目录型 source 里 28 处是 supporting，「仓库结构与目录地图」这类页面列目录是合理写法，只有 primary 写目录才是静默假阴性；(2) 2026-07 期间生成的一批 wiki 用 secondary 而非 schema 规定的 supporting，这个取值在反向映射里既不算 primary 也不算 supporting，被整个忽略，是又一个静默假阴性，影响约 20 份 wiki；(3) 工作区级 wiki 的 source_files 是相对工作区根写的，而 index.json 里没有任何字段记录这一点，用仓库根去校验会把全部源码报成缺失——我自己扫描时就误判了一次。

## 改造目标
目录型 source 只在 primary 时报错、supporting 走 notes；secondary 作为历史别名被脚本兼容并可一键迁移；源码根写进 schema，猜错时有明确提示而不是几十条误报。

## 用户文档影响分析
1. README.md：无需改。 2. docs/usage.md：Δ.-1 分流补 source_is_directory 的 primary/supporting 区分。 3. docs/maintainers.md：无需改。

## 改造主体步骤
1. delta-schema.py：目录型 source 仅 primary 报 source_is_directory，supporting 进新增的 notes[]；role 接受 secondary 别名并在 notes 提示可迁移；新增 source_root_mismatch 启发式（超过半数源码路径缺失时提示根目录给错）；validate 输出新增 notes[] 字段。 2. delta-git.py 反向映射同样把 secondary 当 supporting，否则这些条目被忽略。 3. migrate-meta.py v2→v2 顺手把 secondary 改写为 supporting。 4. meta-schema.json 新增可选 source_root 字段，role 枚举补 secondary 并注明是历史别名。 5. phase-delta-protocol.md 补 source_is_directory 的批量处理三选一与 source_root_mismatch 的处理；meta-schema-fields.md 补 source_root 与 role 别名说明。 6. 同步 docs/usage.md 与 agent-prompt-spec.md。
