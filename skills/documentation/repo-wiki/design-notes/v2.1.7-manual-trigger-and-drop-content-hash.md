# 升级 Plan：v2.1.7 — manual-trigger-and-drop-content-hash

生成时间：2026-10-11 13:20

## 改造背景

1. **Zed 加载失败**：`SKILL.md` 文件头的 `description` 没加引号，内容里又有 `Triggers on: "…"`。「冒号 + 空格」在严格的 YAML 解析器里会被当成新的键值对，Zed 因此提示 `Invalid YAML frontmatter`。Claude Code 的解析较宽松，能正常加载，所以一直没暴露。
2. **自动触发**：skill 靠 `description` 里的一串触发短语，由模型根据对话内容自动启动。维护者希望只在明确输入命令时才启动。
3. **内容 hash 没有必要**：skill 会把 `SKILL.md + references/** + scripts/**` 算成一串指纹存在 `CHANGELOG.md` 顶部，每次使用时比对。它唯一的产出是开场卡片上一行不阻断的警告；代价是每次手改（比如上面的引号修复）都要多跑一步收尾刷新指纹，否则警告一直挂着。skill 放在 git 仓库里由单人维护，改没改过 git 就能看到。`SKILL.md` 顶部的 `<!-- skill-content-hash: PLACEHOLDER -->` 占位行没有任何脚本读取。
4. **`--upgrade --recover` 失去用途**：它主要用来在手改后刷新 hash。hash 去掉后只剩「补一条 CHANGELOG 条目」，不值得单独保留一种用法。

## 改造目标

- 严格解析 YAML 的工具（如 Zed）能加载这个 skill。
- 只有输入 `/repo-wiki` 才会启动，不再根据对话内容自动触发。
- 手改 skill 文件后不再出现警告，也不需要额外的收尾步骤。自检只保留一项：`SKILL.md` 的版本号与 CHANGELOG 最新条目是否一致。
- 收尾固定段从 8 步减为 7 步；`release-finalize.sh` 只剩带 plan 的一种用法。
