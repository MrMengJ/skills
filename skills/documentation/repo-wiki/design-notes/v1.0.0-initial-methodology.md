# 升级 Plan：v1.0.0 — initial-methodology

> 重建于 2026-09-04：原 plan 已丢失，内容按 2026-05-12～05-13 的会话记录与 `x6/claude-repo-wiki/METHODOLOGY.md` 归纳。

## 改造背景
在 `@jecn/x6`（fork 自 antv/x6 1.32.2 的私有项目）上对比 Qoder 生成的 `.qoder/repowiki`：Qoder 广度够（约 108 页、API 参考完整、有 mermaid），但几乎不解释「为什么这样设计」，也不知道 fork 特有改动（Hook 机制、Ghost Drag、beforePaste 等）。手工用 Claude 生成的 `claude-repo-wiki/`（119 页）深度有余、参考型内容不足，且第五轮照抄了 Qoder 目录结构。需要把经验沉淀成可跨项目复用的方法论与 skill，而不是每个项目从头来。

## 改造目标
- 一份《Repo Wiki 生成方法论》：区分参考型（WHAT）与概念型（WHY + HOW）两类文档，五阶段流程（项目指纹 → 现有 wiki 审计 → 独立源码分析 → 结构设计 → 分批生成与质检）。
- 一个 `repo-wiki-generator` skill，把方法论、两类页面 prompt 模板、质量检查清单固化下来。
- 工程约束：逐页处理防 600 秒 watchdog、mermaid 禁止字面 `\n`、源码引用精确到行号、并行 agent 每批 ≤ 8–10 个。

## 用户文档影响分析
首版，无既有用户文档；README 随 skill 一并新建。

## 改造主体步骤
1. 从 x6 的 HANDOFF.md / METHODOLOGY.md 提炼通用部分，去掉 x6 专属内容（GROUND_TRUTH 复制、TypeScript 代码块等）。
2. 写 SKILL.md：触发词、五阶段流程、两类页面模板、并行 agent 策略。
3. 增加验证脚本：`check-dead-links.py`、`check-mermaid.py`、`wiki-stats.py`。
4. 在 x6 上用 `.repowiki/` 输出目录做一次完整生成验证。
