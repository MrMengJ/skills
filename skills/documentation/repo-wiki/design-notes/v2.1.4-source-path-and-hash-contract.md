# 升级 Plan：v2.1.4 — source-path-and-hash-contract

生成时间：2026-09-05 13:48

## 改造背景
iteration-4（v2.1.3）22/22 无回归，同时暴露 4 个仍存在的正确性问题：(1) validate 用 exists() 判断 source_files 路径，目录被放行——真实产物里第 08 章的 source 就是目录 .agents/notes，导致该章永远不会被判为受影响，是一个静默的假阴性；(2) GLOSSARY.md 自 v2.1.1 起是硬要求，但没有任何脚本或检查项确认它存在；(3) content_sha256_normalized 的口径只在文档里用一句话描述，评测中 agent 照描述自行实现算出的值与脚本不一致，若不察觉首次 --update 会把每一页都误判为手动改动冲突；(4) primary_type 枚举没有桌面应用/前端应用类型，Electron 项目只能落到 other。另有两处措辞遗漏：章节 README 需配 README.json 只写在参考文件的兼容说明里；首次生成收尾没说 last_synced_commit 要写完整 hash。

## 改造目标
目录型 source 路径在 Δ.-1 被拦截而不是静默假阴性；GLOSSARY.md 与章节 README.json 进入验证清单；sha256 的取值方式收敛为「调脚本」并写清算法；枚举覆盖桌面/前端应用。

## 用户文档影响分析
1. README.md：无需改。 2. docs/usage.md：Δ.-1 分流补 source_is_directory，脚本表补 GLOSSARY 报告，故障排查新增两条。 3. docs/maintainers.md：无需改。

1. delta-schema.py：source path 为目录时报 source_is_directory（options: expand/typo/skip），非文件才报 missing_source_file。 2. wiki-stats.py 报告 GLOSSARY.md 是否存在。 3. meta-schema.json：primary_type 补 desktop-app/frontend-app/nodejs-cli，source_files[].path 补目录约束说明。 4. meta-schema-fields.md 新增「normalize 口径」一节写清四步算法并要求调脚本取值。 5. SKILL.md：Δ.-1 行给出完整命令；章节 README 需配 README.json；验证通过标准加 GLOSSARY 与 README.json 两项；首次生成收尾说明 last_synced_commit 写完整 hash；schema 字段表强调 sha256 用脚本取。 6. agent-prompt-spec.md 补 source_files 只写文件、sha256 由调度器统一计算。 7. 同步 docs/usage.md。
