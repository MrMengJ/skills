# 升级 Plan：v2.0.0 — decision-points-and-incremental-update

> 重建于 2026-09-04：原 plan 已丢失，内容按 2026-05-13 21:30 的十条改进意见与 05-14 的讨论记录归纳。

## 改造背景
v1 在 x6 上跑通后暴露的问题（用户原话摘要）：
1. 入口点探测写死 `find . -name "index.ts"`，对后端 / 公共库 / CLI 不成立。
2. `git log` 统计 fork 改动意义不明确。
3. 页面模板复制到 `.repowiki/.templates/` 用途不清。
4. 输出目录写死 `.repowiki`，应询问用户。
5. 代码更新后应能按 git commit 增量更新 wiki。
6. 「TypeScript 库典型 14 章结构」写死在 skill 里。
7. 「五轮执行计划」写死，且每轮固定暂停；应在开始前问用户要不要暂停。
8. 逐页处理规则可能导致读源码不足 → 需要补读待办化。
9. watchdog 是谁的机制要说清楚。
10. 「维护者指南」概念过于定向，业务项目不存在「使用指南」；受众要弱化为可选。
另外：skill 升级本身没有流程，plan 存在 `.claude/plans/` 与 Claude 强绑定、可能被删；需要使用文档。

## 改造目标
- 更名 `repo-wiki`，触发词统一 `/repo-wiki`。
- Phase 0 决策点 D1–D5（受众 / 语言 / 章节草稿 / 输出目录 / mermaid）+ C1 暂停偏好；参数复述原则。
- 章节规划改为启发式 A–H 从项目推导；轮数由章节数决定。
- 增量更新：`--update` / `--rebuild` / `--dry-run`，`.wiki-meta/` 记录 `last_synced_commit` 与每页 `source_files`（primary / supporting）、`content_sha256_normalized`。
- `--upgrade` 自升级：进入 plan 模式收集需求 → 执行 → plan 拷贝到 `design-notes/`（与 Claude 目录解耦）→ CHANGELOG。
- 项目类型 / 入口点按构建文件与框架约定探测；补读待办化 `.followup-<agent-id>.md`。
- 新增 README / docs/usage.md / docs/maintainers.md；升级收尾加入「审查是否更新使用文档」。
